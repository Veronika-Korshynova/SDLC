# Описания акторов и вариантов использования системы

## Акторы

| Актор | Описание |
|---|---|
| Пользователь | Настраивает параметры питания, формирует и просматривает недельное меню, заменяет блюда, получает список покупок, сохраняет и открывает планы. |
| Менеджер каталога | Изменяет каталог рецептов, используемый системой для подбора блюд. |

## UC-01 — Настроить профиль

**Пояснение.** Пользователь задаёт или изменяет целевые значения калорийности, белков, жиров и углеводов.

**Предусловия.** Пользователь открыл систему и выбрал настройку профиля.

**Основной поток событий:**
1. Система открывает форму настройки профиля.
2. Пользователь вводит целевые показатели КБЖУ.
3. Пользователь выбирает сохранение изменений.
4. Система сохраняет данные профиля.

**Альтернативный поток.** Пользователь выбирает отмену; новые значения не сохраняются.

**Постусловия.** При сохранении новые параметры доступны для формирования меню; при отмене сохраняются предыдущие параметры.

## UC-02 — Задать ограничения

**Пояснение.** Пользователь указывает аллергены, предпочитаемые и исключённые продукты, учитываемые при подборе блюд.

**Предусловия.** Открыта форма редактирования профиля.

**Основной поток событий:**
1. Пользователь задаёт список аллергенов.
2. Пользователь указывает предпочитаемые и исключённые продукты.
3. Пользователь сохраняет настройки.
4. Система сохраняет ограничения в профиле.

**Альтернативный поток.** Пользователь отменяет изменения; ранее сохранённые ограничения остаются без изменений.

**Постусловия.** Сохранённые ограничения применяются при генерации меню и замене блюда.

## UC-03 — Сформировать меню

**Пояснение.** Система составляет недельное меню на основании сохранённых параметров питания и данных каталога рецептов.

**Предусловия.** Пользователь запросил формирование меню; для успешной генерации параметры профиля должны быть заполнены.

**Основной поток событий:**
1. Пользователь запрашивает меню на семь дней.
2. Система получает сохранённые параметры питания и проверяет их.
3. Система запрашивает в каталоге рецепты с проверенным составом.
4. Каталог передаёт рецепты, ингредиенты и КБЖУ.
5. Система исключает рецепты с запрещёнными ингредиентами и аллергенами.
6. Система подбирает блюда на семь дней и рассчитывает КБЖУ и отклонения от целей.
7. Система отображает недельное меню и показатели КБЖУ.

**Альтернативные потоки:**
- А1. Параметры профиля не заполнены: система направляет пользователя на заполнение профиля; меню не формируется.
- А2. Подбор невозможен: система сообщает о конфликте ограничений; меню не формируется.

**Постусловия.** При успехе пользователь видит сформированное меню и КБЖУ. При неуспехе ранее сохранённый план не изменяется.

## UC-04 — Просмотреть план и КБЖУ

**Пояснение.** Пользователь просматривает состав недельного меню и его пищевую ценность.

**Предусловия.** Недельное меню сформировано или открыт сохранённый план.

**Основной поток событий:**
1. Пользователь открывает план.
2. Система отображает дни и блюда недельного меню.
3. Система показывает КБЖУ блюд, дней и недели, а также отклонения от целевых значений.

**Альтернативный поток.** Если формирование меню завершилось неудачей, вместо плана отображается сообщение о невозможности подбора.

**Постусловия.** Пользователь получает сведения о меню; состав плана не изменяется.

## UC-05 — Посмотреть рецепт

**Пояснение.** Пользователь получает подробные сведения о выбранном блюде.

**Предусловия.** В плане доступно блюдо, рецепт которого пользователь хочет открыть.

**Основной поток событий:**
1. Пользователь выбирает отдельное блюдо.
2. Система отображает КБЖУ блюда.
3. Система показывает рецепт, ингредиенты и количества, число порций и инструкцию приготовления.

**Альтернативный поток.** Если данные рецепта недоступны, сведения о рецепте не могут быть отображены.

**Постусловия.** Рецепт просмотрен; меню не изменено.

## UC-06 — Заменить блюдо

**Пояснение.** Пользователь заменяет одно блюдо в меню допустимым альтернативным рецептом.

**Предусловия.** Меню сформировано или открыт сохранённый план; выбрано блюдо для замены.

**Основной поток событий:**
1. Пользователь выбирает блюдо для замены.
2. Система запрашивает допустимые альтернативы в каталоге рецептов.
3. Каталог возвращает альтернативные рецепты.
4. Система проверяет аллергены и ограничения.
5. Система отображает подходящие варианты.
6. Пользователь выбирает заменяющее блюдо.
7. Система заменяет только выбранное блюдо и пересчитывает КБЖУ и список покупок.
8. Система показывает обновлённое меню и показатели.
9. Пользователь сохраняет изменения меню.

**Альтернативные потоки:**
- А1. Подходящих альтернатив нет: система сообщает о невозможности замены; меню остаётся прежним.
- А2. Пользователь отменяет внесённые изменения: изменения меню не сохраняются.

**Постусловия.** При успешном сохранении заменено одно выбранное блюдо, показатели КБЖУ и список покупок обновлены; при отмене или невозможности замены изменений нет.

## UC-07 — Получить список покупок

**Пояснение.** Пользователь просматривает необходимые для недельного меню продукты и их количества.

**Предусловия.** Меню сформировано или открыт сохранённый план.

**Основной поток событий:**
1. Пользователь запрашивает список покупок.
2. Система собирает ингредиенты блюд плана с учётом порций.
3. Система суммирует количества одноимённых ингредиентов в совместимых единицах измерения.
4. Система отображает список покупок.

**Альтернативный поток.** Несовместимые единицы измерения не суммируются автоматически.

**Постусловия.** Список покупок отображён; план не изменён.

## UC-08 — Сохранить план

**Пояснение.** Пользователь сохраняет сформированное или изменённое недельное меню для дальнейшего использования.

**Предусловия.** Недельное меню сформировано либо открытый план изменён.

**Основной поток событий:**
1. Пользователь выбирает сохранение плана.
2. Система сохраняет меню и связанные с ним настройки.
3. Сохранённый план становится доступен для последующего открытия.

**Альтернативный поток.** Пользователь отменяет изменения меню до сохранения; несохранённые изменения не применяются.

**Постусловия.** При успешном сохранении план доступен пользователю при последующем открытии.

## UC-09 — Открыть сохранённый план

**Пояснение.** Пользователь возвращается к ранее сохранённому недельному меню.

**Предусловия.** У пользователя имеется сохранённый план.

**Основной поток событий:**
1. Пользователь запрашивает открытие сохранённого плана.
2. Система загружает план.
3. Система отображает меню и показатели КБЖУ.
4. Пользователь может продолжить просмотр или редактирование меню.

**Альтернативный поток.** Если сохранённый план отсутствует, открыть его невозможно.

**Постусловия.** Сохранённый план открыт для просмотра и дальнейших действий.

## UC-10 — Изменить каталог рецептов

**Пояснение.** Менеджер каталога изменяет сведения каталога рецептов, используемые системой при формировании меню.

**Предусловия.** Менеджеру каталога доступно изменение каталога рецептов.

**Основной поток событий:**
1. Менеджер каталога выбирает данные рецепта для изменения.
2. Менеджер вносит изменения в сведения о рецепте, ингредиентах, массах или КБЖУ.
3. Изменённые данные сохраняются в каталоге.

**Альтернативный поток.** Если состав или пищевая ценность рецепта не проверены, рецепт не включается в автоматический подбор меню.

**Постусловия.** Каталог содержит изменённые данные рецептов; автоматический подбор использует только рецепты с проверенным составом.
